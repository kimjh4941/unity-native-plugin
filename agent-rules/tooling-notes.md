# エージェントの道具の注意（Windows）

Windows でエージェントがファイルを生成・書き換えるときに、黙って壊れた実例と回避策。
どれも検査や `grep` では普通に見え、挙動を追うまで気付けなかったもの。

## シェルに渡したスクリプトで、バックスラッシュが 1 段消える

Bash ツールで `python - <<'PY'` や `cat > f <<'PYEOF'` にスクリプトを渡すと、
**クォート付きのヒアドキュメントでもバックスラッシュが 1 段消費される。**
非 raw の Python 文字列に `\\b` と書くと、ファイルには `\b` ではなく **バックスペース文字 0x08** が入る。

- 実例（2026-09-09）: `check_design_consistency.py` を直す過程で 3 回起きた。正規表現の `\bdist\b` が制御文字になり、除外が黙って無効になった
- 回避:
  - 生成するスクリプトは、ファイルを書く道具でファイルに書いてから実行する。シェルのヒアドキュメントに埋めない
  - 生成スクリプトの中のコード片は `r'''...'''` で書く
  - 正規表現をファイルに埋めたら、制御文字が無いことを確かめる（`{c for c in open(f, 'rb').read() if c < 9 or 13 < c < 32}` が空）
  - バックスラッシュを避けられる書き方があるなら、そちらを選ぶ（文字列リテラルの除去は、正規表現でなく `split('"')` で足りた）
  - 確認用のワンライナーも、`python -c "..."` の中の `\` は bash の二重引用符で 1 段落ちる

## 改行コード

- **Windows の `Path.write_text()` は LF を CRLF に変える**（テキストモードで `\n` を `os.linesep` にするため）。
  2026-09-26、LF の `scripts/verify_unity_windows.sh` を `read_text` / `write_text` で書き換えたら、全 178 行が CRLF になった。bash は CRLF の行を実行できない
- シェルスクリプトやバイナリに近いファイルは、`read_bytes()` / `write_bytes()` で扱い、改行を変えない
- 置き換えは、ファイルの改行を判定して `\n` にそろえてから行い、書くときに元の改行に戻す。二重に変換すると一致しなくなる
- 書いた後に CRLF と LF の行数を数え、`git show HEAD:<path>` と同じ方式か確かめる

## 日本語の長い行を含む .py

日本語を含む長い行（数百文字）のある .py を `python file.py` で動かすと、
Python 3.9 が `SyntaxError: Non-UTF-8 code starting with '\xe5'` で止まることがある（2026-09-27、2026-10-03 にも再発）。中身は正しい UTF-8 で、decode も通る。

- 回避: 読んでから `exec` する。`python -c "exec(open(r'<path>', encoding='utf-8').read())"`。コーディング宣言を足すより確実

## 置き換えスクリプトの書き方

- 置き換える文字列が **ちょうど 1 回** 出ることを `count == 1` で確かめてから置き換える。0 回や 2 回以上なら止める
- 自分で決めた検査（「古いパスが残っていない」など）が、意図して残した箇所で止まることがある。止まったら、書き込む前に止まったことを確かめてから、検査の対象を絞る

## 「0 件」を成功と読まない

`rglob` が壊れたシンボリックリンク（`Plugins/macOS/*.xcframework` の `Versions/Current`）で例外を投げ、
全ドキュメントで **FAIL 0 件** に見えたことがある。ファイルを列挙するときは `git ls-files` を使うか、存在を確かめる。
「0 件」を成功と読む前に、わざと壊した入力で FAIL するか確かめる。

## リポジトリ全体の検索

`grep -r` をリポジトリの直下で回すと、Unity の `Library/` まで読んで 2 分を超える。
検索の範囲を `agent-rules`、`artifact`、`scripts`、`Packages/com.jonghyunkim.nativetoolkit` などに絞るか、`git grep` を使う。
