### R-1: 公開 enum が「5 値固定」と一致しない

- **分類: C**（記述の誤り。安全性の結論は変わらない）
- 該当: design-v2 `§6.6` の #14、`D-14`

**裏取り結果: 事実。6 値である。**

```
Default, Ask, AlwaysAllow, AlwaysDeny, Unavailable, Unknown
```

v2 は「5 値固定で利用者データを含みえない」と書いていた。**閉じた C# enum なので表示して安全という結論は変わらない**が、根拠として書いた数が誤り。

6 つ目の `Unknown` は、ネイティブが未知の文字列を返したときのフォールバックである（`MacClipboardJsonParser.TryParseAccessBehavior` が `ParseAccessBehavior` で解決できない値を `Unknown` に落とす）。**`Unknown` が出ることは「ネイティブが新しい case を得た」というシグナル**であり、`v12 §7.5` #14 でも観測できる必要がある。

### R-2: エラー追跡の母集団と正規化表が到達可能コードを落としている

- **分類: A1**（実装しても気づけない。実機確認の網が穴あきのまま通る）
- 該当: design-v2 `§3.4`（追跡集合）と `§4.6`（正規化表）

**裏取り結果: 2 箇所とも事実。しかも欠落は Codex が示唆したより多い。**

**(a) 追跡集合**: v2 は 8 件（1503 / 1508 / 1512 / 1523 / 1302 / 1511 / 1515 / 9007）。しかし `v12 §7.5` がコードを名指しする項目を数えると **10 件**である。

```
1302 1503 1508 1511 1512 1513 1514 1515 1523 9007
```

**欠落は 1513 と 1514。** どちらも環境依存で到達する（1513 は macOS 15.4 未満、1514 は利用者が許可ダイアログで拒否したとき）。集合から漏れると「押したのに増えない」のか「そもそも到達しない環境なのか」を画面から区別できない。

**(b) 正規化表**: v2 は 14 件を列挙。`MacClipboardErrorCodes` の `public const int` は **29 件**である。**欠落 15 件のうち、1514（7.5 #12 が名指し）と 1599（ほぼ全操作の受け皿）が実害の大きいもの。** 抜けたコードは `unmapped` に落ちるため機微情報は漏れないが、画面から何が起きたのか分からなくなる。

### R-3: #4 / #25 の判定規則がまだ一意でない

- **分類: A1**（誤判定に気づけない）

v2 は「直前の `Copy` が本アプリからでない場合は `n/a`」と書いていたが、**それを判定する手段を定義していなかった。**

壊れる筋道:

1. `CopyUnicodeButton` を押す（自分が書く）
