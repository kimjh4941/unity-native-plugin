# Godot への展開は、Clipboard の完成後に需要を見て決める

- 記録日: 2026-07-24（決定）。リポジトリへの記録は 2026-10-03（それまでエージェントのメモリにだけあった）
- 分類: 横断課題（展開方針）
- 発見経緯: native-toolkit を Godot にも展開するかを議論したとき（2026-07-24）
- 対応方針: **急がない。** まず Clipboard を全プラットフォームで完成させてコア API を確定させ、その後に世間の反応と需要を見て、展開するかを決める
- 進捗: 未着手（判断待ち）

---

## 決めたこと（2026-07-24）

- 技術的な前提（上流の native-toolkit で、コアライブラリとエンジン向けのバインディングが 2 層に分かれていること）は、4 プラットフォームすべてで満たされている
- したがって、判断の軸はアーキテクチャの障害ではなく、**需要とメンテナンスの負荷**

## 同じ議論で確認した優先順位

1. Clipboard（当時、README の Planned Features にある唯一の項目。全プラットフォームで実需がある）
2. 同梱しているネイティブのバイナリを、上流の dist に合わせる
3. Godot への展開の判断（需要しだい）

**Windows の Share は優先度を下げる。** デスクトップで OS の共有シートを使う導線が薄く、上流の `WindowsLibrary` にも Share の実装が無いので、ネイティブから作る必要がある。

## 今の状況（2026-10-03）

- Clipboard は Android / iOS / macOS / Windows で実装済み（`manual/1.12.0/clipboard.md`）
- 同梱のバイナリは、Windows では native-toolkit 1.12.0 のタグの dist と同じものにした（`Plugins/Windows/VERSION.txt`、リリースの確認の「Windows DLL の整合」）。Android / iOS / macOS は確かめていない
- つまり 1 は済み、2 は Windows だけ済んだ。3 の判断はまだしていない
