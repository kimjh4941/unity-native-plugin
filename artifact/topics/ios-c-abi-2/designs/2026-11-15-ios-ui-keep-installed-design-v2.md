# iOS UI テストの「入れ直さない」実行の設計 v2

v1 からの変更は [レビュー v1](../reviews/2026-11-15-ios-ui-keep-installed-design-review-v1.md) の 3 章の判断による（6 章に一覧）。

## 基本情報

| 項目 | 内容 |
|---|---|
| 目的 | 実機で Notification の UI テスト（[Notification の計画 v4](../../../ios/notification/designs/2026-11-14-ios-notification-ui-test-plan-v4.md) の `2.2` の NU-1・4・5・7・11）を流す。集中モードの「許可するアプリ」にハーネスを足してもらうため、ハーネスを 1 回だけ入れ、テストのあいだ入れ直さない |
| 何の差分か | [UI の自動化の設計書 v4](2026-11-14-ios-ui-automation-design-v4.md) の `4.6`（ランナーと実機の守り）。ほかの所は変えない |
| 背景 | 段 2 の実機の回（README の `6.6`）: おやすみモードでは、許可するアプリに入っていない通知のバナーは出ない。ハーネスはテストのたびに入れ直すので、許可するアプリに入れておけない。native-toolkit は、サンプルを先に入れて利用者が許可し、入れ直さずに流す（`agent-rules/device-testing.md` の「準備」） |
| 準備（利用者） | **集中モードで通知を許すアプリを「NTK UI Harness」だけにする**（人と時間指定の通知の割り込みも許さない。足りなければ試験用の集中モードを作ってもらう）。予定で始まる別の集中モードが流す時間に重ならない。ロックを解除し、自動ロック「なし」、給電。所要は 30〜40 分（待ちを除く）。終わったら、集中モードの許可するアプリからハーネスを外してもらう（消えたアプリの項目が残るかは測っていない） |
| 守ること | native-toolkit の `device-testing.md`。端末の設定は agent から変えない（利用者が足す）。ハーネスの通知のほかを読まない・押さない。失敗の文に springboard のラベルを書かない。終わりに入れたアプリをすべて消す |

## 1. 何を足すか

### 1.1 区分と一覧（`DeviceRequirements.json`）

- 新しい区分 `focus`: 「ハーネスを 1 回だけ入れ、利用者が集中モードで通知を許すアプリをハーネスだけにするのを待ってから、入れ直さずに続けて流す」。`longpress`（NU-5）: 「ハーネスの通知のバナーを長押しし、広がった中身がその通知であることを確かめてから、その中の action だけを押す」。5 件の区分から `reinstall` を外す
- 新しい欄 `keepInstalled`: 入れ直さない実行で流すテストの**順の決まった一覧**（`NotificationUITests/test_NU1`、`test_NU4`、`test_NU5`、`test_NU7`、`test_NU11`）。NU-1 は権限を「許可」にするので、必ず先頭
- `keepInstalled` のテストは、`simulatorOnly` から外す。ただし**入れ直す実行（今の `--device`）では選べない**（`ios_ui_runner.py tests --device` は出さない。`--tests` で名指ししても断る）。逆に、入れ直さない実行では `keepInstalled` の外のテストを断る
- **照らしは Python の側で行う**（シェルだけで守ると、サブコマンドを直に呼べば素通りする）: `tests --keep-installed` は一覧をその順で出す。`approve`・`check-approval`・`use-approval`・`guard` は `--keep-installed` を取り、承認の記録に `keepInstalled` を入れ、形の違いを両方向で問題にする。入れ直さない形ではテストを順ごと比べる（`sorted` にしない）。JSON を読むときに、`keepInstalled` の名前が実在すること、`simulatorOnly` と重ならないこと、重複が無いこと、区分がすべて既知であることを照らす
- **承認の消費は排他にする**: 読み・照らし・使用済みの書き込みを、リポジトリの外の lock の中で行い、記録は一時ファイルからの rename で書く（今の入れ直す実行にも効く）

### 1.2 ランナー（`scripts/test_ios_ui.sh --device --keep-installed`）

```
scripts/test_ios_ui.sh --device --keep-installed --dry-run
scripts/test_ios_ui.sh --device --keep-installed --approved <ID>
```

- `--tests` は取らない。流すのは `keepInstalled` の一覧の全部を、その順で
- `--dry-run` の一覧に次を足す: 「ハーネスを 1 回だけ入れる」「入れた後、利用者が集中モードの許可するアプリに『NTK UI Harness』を足すまで止まる（最長 30 分）」「最初のテストが通知の許可のダイアログで『許可』を押す」「終わりに（途中で止まっても）3 つのアプリを消す」。承認の記録に `keepInstalled: true` を入れ、`--keep-installed` の無い実行では使えない（逆も同じ）
- 流れ:
  1. 今と同じく、承認を使い、ハーネスと UI テストを組む（端末に触れる前に照らす）
  0. リポジトリの外の lock（`~/Library/Application Support/unity-native-plugin/test_ios.lock`）を取る。取れなければ止まる（待っている実行のハーネスを、別の実行が「前に残ったもの」として消さないように）
  2. 前に残ったハーネスを `remove_from_device`（消えたことを読み直す）で消し、消えたと確かめられなければ止まる。照らしてから、ハーネスを 1 回だけ入れる
  2b. **NU-1 を先に流す**（バナーを使わない。入れた直後に許可を求めて「許可」になることを確かめる）。ハーネスが「設定 > 通知」に載ってから、利用者が集中モードに足せる
  3. **止まる**: 準備の案内（基本情報の「準備」）と「済んだら `<準備の印のファイル>` を作ってください」を出し、印のファイルができるのを待つ。準備の印は、照らしの marker とは別に、入れた後に作るランダムな値（シミュレーターでも同じに作る）。印のファイルはリポジトリの外（`~/Library/Application Support/unity-native-plugin/test_ios-ready/<準備の印>`）で、普通のファイルでなければ（場所やリンクなら）認めない。終わりに消す。30 分で来なければ、テストを始めずに後片付けへ進む。待つ間も 15 秒ごとに状態を出す（見張りが止まりと見分けられるように）。取り消しは TERM か取り消しの印のファイル（`<準備の印>.cancel`）で行い、KILL は使わない。待つ間は `caffeinate -i` で Mac を起こしておく
  3b. 印を認めたら、照らし直し（`device_guard`）、時間の限りを付けた `devicectl device info details`（読むだけ）で開発用の接続を確かめる。どちらかが駄目ならテストを始めずに後片付けへ進む
  4. 一覧の残り（NU-4・5・7・11）の順に、テストごとに照らしてから `test-without-building -only-testing` を呼ぶ（**入れ直さない**。`TEST_RUNNER_NTK_KEEP_INSTALLED=1` を付ける）。どれかが落ちても、残りは流さずに後片付けへ進み、流さなかったテストは `did not run (an earlier test failed)` と出す
  5. 後片付け: 今と同じく、入れた 3 つのアプリを消し、消えたことを確かめる。trap でも同じ。消し終えて確かめてから「済んだ」の印を立てる（消している途中で止められても、trap が残りを消す）。確かめられなければ「NTK UI Harness を手で消してください」と出す。終わりに、集中モードの許可するアプリからハーネスを外すよう案内する
  6. 待っている間に agent は guarded の木を変えない・コミットしない（HEAD が動けば止まり、利用者の準備が無駄になる）
- agent が流すとき、手順 3 の印のファイルは、利用者が「足した」と伝えた後に agent が作る（利用者の端末の設定を agent が変えることはない）

### 1.3 テストの側（`NotificationUITests`）

- 実行の形は環境変数 `NTK_KEEP_INSTALLED`（ランナーが `TEST_RUNNER_NTK_KEEP_INSTALLED=1` で渡す）でテストに伝える。NU-1 は今のまま、ダイアログが必ず出ることを求める。入れ直さない実行の 2 つ目以降の `grant()` は、**ダイアログが出ないことを 3 秒照らし**、押さずに `[permission@ok] granted` を照らす（出たら、入れ直されたか権限が戻された異常なので落とす）。入れ直す実行（シミュレーター）は今のまま
- 入れ直さない実行では、各テストの初めに `pending` と `delivered` の行で `ntkh-` の通知が無いことを照らす。`tearDown` は片付けの後に、両方が空になるまで待つ
- 各テストは今と同じく、`tearDown` で片付けの行（`CancelAllNotifications`、`RemoveAllDeliveredNotifications`）を押す。前のテストの通知が次のテストのバナーの探し方に当たらないよう、本文はテストごとに違う（`ntk NU-<n>`）
- バナーは題と本文で 1 件に絞ってから押す。長押しの前に、そのバナーが押せる（`isHittable`）ことを照らす。長押しの後は、広がった通知の中身（題と本文）がその通知であることを確かめ、**その通知の入れ物の中だけで** action を探して押す（native-toolkit の `Springboard.expandedScope` の形。iOS 18.3 の入れ物の識別子は、シミュレーターで測ってから決める）。確かめられなければ何も押さず、ホームを押して戻す

## 2. 選ばなかった案

| 案 | 選ばなかった理由 |
|---|---|
| ハーネスを端末に入れたままにする（テストの回をまたぐ） | 承認の一覧の「終わりに消す」が崩れる。利用者の端末に、承認していないものが残る |
| 集中モードを使わず、おやすみモードを切ってもらう | 私物の通知の割り込みで UI テストが落ちる（native-toolkit の `device-testing.md`）。利用者もおやすみモードのままと決めた |
| 止まらずに、許可するアプリに足してあることを前提に流す | ハーネスは入れた直後なので、足してあることはありえない |
| 端末の操作で集中モードの設定を agent が変える | `device-testing.md` で禁じられている |

## 3. テスト

- `ios_ui_runner.py` の docstring の doctest（`python3 -I -m doctest scripts/ios_ui_runner.py` で流す）に足す: `keepInstalled` のテストが `tests --device` に出ないこと、形の違いを両方向で断ること、順の違いを断ること、`guard` で形を照らすこと、JSON の照らし、同じ承認を 2 回消費できないこと
- シェルの部分は、端末の操作をまねる関数に差し替えて流す（シミュレーターの回とは別）: 偽の印・別の実行の印・場所の印を認めないこと、待つ間に HEAD が動いたら始めないこと、待ちの時間切れ、TERM で止めたときに後片付けが最後まで走ること、消している途中で TERM を受けても残りを消すこと、走っている間に編集した `ProjectSettings` が終わりに戻されないこと
- シミュレーターで `--keep-installed` を流す（印のファイルを agent が作る）。シミュレーターでは集中モードは関係ないが、入れ直さずに 5 件が順に通ることと、後片付けを確かめる
- 実機は、利用者の準備（集中モード）と許可を得てから流す

## 4. 今のランナーにもある穴（この設計を待たずに直す）

- 終わりの `restore_side_effects` は、Unity の段の直後に戻した後も実行の終わりにもう一度走り、走っている間に人が編集した `ProjectSettings` などまで戻す（Codex の KI-01）。Unity の段の直後に戻し終えたら、終わりの一括の戻しは、Unity の段が途中で止まったときだけにする
- `clean_up_apps` は消す前に「済んだ」の印を立てるので、消している途中で止められると trap が残りを消さない（Codex の KI-02）。消し終えて確かめてから印を立てる

## 5. 決めていないこと

- 印のファイルの代わりに、端末の上でハーネスが「許可するアプリに入っている」ことを確かめる方法は無い（集中モードの設定はアプリから読めない）。足し忘れは、NU-4 のバナーが出ないことで分かる（落ちて後片付けに進む）
