# iOS UI テストの「入れ直さない」実行の設計 v4

**レビュー v3（[../reviews/2026-11-15-ios-ui-keep-installed-design-review-v3.md](../reviews/2026-11-15-ios-ui-keep-installed-design-review-v3.md)）で 2 人とも A1 が 0 になり、止めた。** v4 は止めた後の直しで、レビューに出していない（8 章）。

v1 からの変更は [レビュー v1](../reviews/2026-11-15-ios-ui-keep-installed-design-review-v1.md)、v2 からの変更は [レビュー v2](../reviews/2026-11-15-ios-ui-keep-installed-design-review-v2.md) の 3 章の判断による（6 章と 7 章に一覧）。

## 基本情報

| 項目 | 内容 |
|---|---|
| 目的 | 実機で Notification の UI テスト（[Notification の計画 v4](../../../ios/notification/designs/2026-11-14-ios-notification-ui-test-plan-v4.md) の `2.2` の NU-1・4・5・7・11）を流す。集中モードの「許可するアプリ」にハーネスを足してもらうため、ハーネスを 1 回だけ入れ、テストのあいだ入れ直さない |
| 何の差分か | [UI の自動化の設計書 v4](2026-11-14-ios-ui-automation-design-v4.md) の `4.6`（ランナーと実機の守り）。ほかの所は変えない |

| 準備（利用者） | **集中モードで通知を許すアプリを「NTK UI Harness」だけにする**（人と時間指定の通知の割り込みも許さない。足りなければ試験用の集中モードを作ってもらう）。予定で始まる別の集中モードが流す時間に重ならない。ロックを解除し、自動ロック「なし」、給電。所要は 30〜40 分（待ちを除く）。終わったら、集中モードの許可するアプリからハーネスを外してもらう（消えたアプリの項目が残るかは測っていない） |

## 1. 何を足すか

### 1.1 区分と一覧（`DeviceRequirements.json`）

- 新しい区分 `focus`: 「ハーネスを 1 回だけ入れ、利用者が集中モードで通知を許すアプリをハーネスだけにするのを待ってから、入れ直さずに続けて流す」。`longpress`（NU-5）: 「ハーネスの通知のバナーを長押しし、広がった中身がその通知であることを確かめてから、その中の action だけを押す」。5 件の区分から `reinstall` を外す。`about` の Notification の文（「every test is simulator only until …」）を、この実行の説明に改める
- 新しい欄 `keepInstalled`: 入れ直さない実行で流すテストの**順の決まった一覧**（`NotificationUITests/test_NU1`、`test_NU4`、`test_NU5`、`test_NU7`、`test_NU11`）。NU-1 は権限を「許可」にするので、必ず先頭
- `keepInstalled` のテストは、`simulatorOnly` から外す。ただし**入れ直す実行（今の `--device`）では選べない**（`ios_ui_runner.py tests --device` は出さない。`--tests` で名指ししても断る）。逆に、入れ直さない実行では `keepInstalled` の外のテストを断る
- **照らしは Python の側で行う**（シェルだけで守ると、サブコマンドを直に呼べば素通りする）: `tests --keep-installed` は一覧をその順で出す。`approve`・`check-approval`・`use-approval`・`guard` は `--keep-installed` を取り、承認の記録に `keepInstalled` を入れ、形の違いを両方向で問題にする。入れ直さない形ではテストを順ごと比べる（`sorted` にしない）。JSON を読むときに、`keepInstalled` の名前が実在すること、`simulatorOnly` と重ならないこと、重複が無いこと、区分がすべて既知であることを照らす
- **承認の消費は排他にする**: 読み・照らし・使用済みの書き込みを、リポジトリの外の lock の中で行い、記録は一時ファイルからの rename で書く（今の入れ直す実行にも効く）

### 1.2 ランナー（`scripts/test_ios_ui.sh --device --keep-installed`）

```
scripts/test_ios_ui.sh --device --keep-installed --dry-run
scripts/test_ios_ui.sh --device --keep-installed --approved <ID>
```

- `--tests` は取らない。流すのは `keepInstalled` の一覧の全部を、その順で
- `--dry-run` の一覧に次を足す: 基本情報の「準備」の全部（集中モードで通知を許すアプリをハーネスだけにする、予定で始まる集中モードが重ならない、ロックの解除、自動ロック「なし」、給電）と所要時間（30〜40 分と、待ちの最長 30 分）。「ハーネスを 1 回だけ入れる」「NU-1 で通知の許可のダイアログに『許可』を押す」「その後、利用者が集中モードの準備をするまで止まる（最長 30 分）」「NU-5 はバナーを長押しする」「終わりに（途中で止まっても）3 つのアプリを消す。集中モードの許可するアプリからハーネスを外すよう頼む」。承認の記録に `keepInstalled: true` を入れ、`--keep-installed` の無い実行では使えない（逆も同じ）
- 流れ（実行の順）:
  1. **実行の lock を取る**: どちらのランナーでも、引数を照らした直後、`require_clean_ios_plugins`・`record_side_effects_baseline`・EXIT の trap より前（したがって承認より前）。`~/Library/Application Support/unity-native-plugin/test_ios-run.lock` を Python の `fcntl.flock` で取り、その fd を持つ小さな見張りの子プロセスが実行の終わりまで持つ。子は TERM・HUP・INT を無視し、親の終了（`getppid()` の変化を 1 秒ごとに見る）か、親からの明示の解放（後片付けの後）でだけ終わる。子は取れたかどうかを 1 行で親に返し、親はそれを読むまで先へ進まない。子が先に終わったら、親は実行を止める。fd は xcodebuild や Unity などの子孫に受け継がせない。取れなければ、後片付けも戻しも走らせずに止まる。lock は、端末か同じシミュレーターに触れる実行が**形を問わずすべて**取る（`test_ios_ui.sh` の全部の形と `verify_unity_ios.sh`）。離すのは取った実行だけで、後片付けの後。fd の lock なので、KILL や再起動の後に古い lock は残らない
  2. 承認を使う（今と同じ）。承認の消費は、実行の lock とは別のファイル（`test_ios-approvals.lock`）を `fcntl.flock` で取り、読み・照らし・使用済みの書き込みの間だけ持つ。記録は一時ファイルからの rename で書く
  3. ハーネスと UI テストを組む（端末に触れる前に照らす）
  4. `DEVICE_TOUCHED=1` を立ててから、前に残ったハーネスを `remove_from_device`（消えたことを読み直す）で消す。消えたと確かめられなければ止まる。照らしてから、ハーネスを 1 回だけ入れる
  5. 照らし、時間の限りを付けた `devicectl device info details` で接続を確かめてから **NU-1 を流す**（バナーを使わない。入れた直後に許可を求めて「許可」になることを確かめる。`TEST_RUNNER_NTK_KEEP_INSTALLED` は付けない）。NU-1 が落ちたら、待たずに後片付けへ進み、NU-4・5・7・11 を `did not run (an earlier test failed)` と出す。ハーネスが「設定 > 通知」に載るので、利用者が集中モードに足せる
  6. **止まる**: 集中モードの準備の案内と「済んだら `<準備の印のファイル>` を作ってください」を出し、印のファイルができるのを待つ。準備の印は、照らしの marker とは別に、手順 4 の後に作るランダムな値（シミュレーターでも同じに作る）。印のファイルはリポジトリの外（`~/Library/Application Support/unity-native-plugin/test_ios-ready/<準備の印>`）で、普通のファイルでなければ（場所やリンクなら）認めない。終わりに消す。30 分で来なければ、テストを始めずに後片付けへ進む（流さなかったテストは `did not run (not ready)` と出し、失敗として数える）。待つ間も 15 秒ごとに状態を出す（見張りが止まりと見分けられるように）。取り消しは TERM か取り消しの印のファイル（`<準備の印>.cancel`）で行い、KILL は使わない。待つ間は `caffeinate -i -w $$` で Mac を起こしておく（実行が終わると一緒に終わる）
  7. 印を認めたら、照らし直し（`device_guard`）、時間の限りを付けた `devicectl device info details --json-output`（読むだけ）で開発用の接続を確かめる。見る欄（tunnel の状態、Developer Disk Image のサービス）は実機の出力で決める。端末を特定する値は書かない。どちらかが駄目ならテストを始めずに後片付けへ進む（流さなかったテストは `did not run` と出し、失敗として数える）
- **シミュレーターの `--keep-installed`**（`scripts/test_ios_ui.sh --keep-installed`。確かめ用）: 手順 2（承認）と手順 7 の接続の確かめは飛ばす。手順 3 の後に今と同じくシミュレーターを起動する（`SIM_BOOTED_BY_US` を含む）。手順 4 は `simctl` で消してから入れる。準備の印は agent が作る
  8. 一覧の残り（NU-4・5・7・11）の順に、テストごとに照らしてから `env TEST_RUNNER_NTK_KEEP_INSTALLED=1 "$XCODEBUILD" test-without-building -only-testing …` を呼ぶ（**入れ直さない**）。どれかが落ちても、残りは流さずに後片付けへ進み、流さなかったテストは `did not run (an earlier test failed)` と出す。ほかの `xcodebuild` は `env -u TEST_RUNNER_NTK_KEEP_INSTALLED -u NTK_KEEP_INSTALLED` で呼ぶ
  9. 後片付け: 今と同じく、入れた 3 つのアプリを消し、消えたことを確かめる。trap でも同じ。消し終えて確かめてから「済んだ」の印を立てる（消している途中で止められても、trap が残りを消す）。確かめられなければ「NTK UI Harness を手で消してください」と出す。終わりに、集中モードの許可するアプリからハーネスを外すよう案内する
- 待っている間（手順 6）は、agent は guarded の木を変えない・コミットしない、このリポジトリで Unity を動かすランナー（シミュレーターを含む）を流さない（HEAD が動けば止まり、利用者の準備が無駄になる。lock で入れ直す実行は始まらないが、照らしの対象は lock の外でも変わりうる）
- agent が流すとき、手順 6 の印のファイルは、利用者が「準備が済んだ」と伝えた後に agent が作る（利用者の端末の設定を agent が変えることはない）

### 1.3 テストの側（`NotificationUITests`）

- 実行の形は環境変数 `NTK_KEEP_INSTALLED`（ランナーが `TEST_RUNNER_NTK_KEEP_INSTALLED=1` で渡す。Xcode の `TEST_RUNNER_` の頭は外れてテストのランナーに渡る）でテストに伝える。NU-1 には付けない。NU-1 は今のまま、ダイアログが必ず出ることを求める。入れ直さない実行の 2 つ目以降の `grant()` は、**ダイアログが出ないことを 3 秒照らし**、押さずに `[permission@ok] granted` を照らす（出たら、入れ直されたか権限が戻された異常なので落とす）。入れ直す実行（シミュレーター）は今のまま
- 入れ直さない実行では、各テストの初めに `pending` と `delivered` の行で `ntkh-` の通知が無いことを照らす。`tearDown` は片付けの後に、両方が空になるまで待つ
- 各テストは今と同じく、`tearDown` で片付けの行（`CancelAllNotifications`、`RemoveAllDeliveredNotifications`）を押す。前のテストの通知が次のテストのバナーの探し方に当たらないよう、本文はテストごとに違う（`ntk NU-<n>`）
- バナーは題と本文で 1 件に絞ってから押す。長押しの前に、そのバナーが押せる（`isHittable`）ことを照らす。長押しの後は、広がった通知の中身（題と本文）がその通知であることを確かめ、**その通知の入れ物の中だけで** action を探して押す（native-toolkit の `Springboard.expandedScope` の形。iOS 18.3 の入れ物の識別子は、シミュレーターで測ってから決める。実機の iOS 18.7.2 で形が違えば、確かめられずに何も押さず NU-5 が落ちるだけで、そのときは実機の回の記録から形を決め直す）。確かめられなければ何も押さず、ホームを押して戻す

## 2. 選ばなかった案

| 案 | 選ばなかった理由 |
|---|---|
| ハーネスを端末に入れたままにする（テストの回をまたぐ） | 承認の一覧の「終わりに消す」が崩れる。利用者の端末に、承認していないものが残る |
| 集中モードを使わず、おやすみモードを切ってもらう | 私物の通知の割り込みで UI テストが落ちる（native-toolkit の `device-testing.md`）。利用者もおやすみモードのままと決めた |
| 止まらずに、許可するアプリに足してあることを前提に流す | ハーネスは入れた直後なので、足してあることはありえない |
| 端末の操作で集中モードの設定を agent が変える | `device-testing.md` で禁じられている |

## 3. テスト

- `ios_ui_runner.py` の docstring の doctest（`python3 -I -m doctest scripts/ios_ui_runner.py` で流す）に足す: `keepInstalled` のテストが `tests --device` に出ないこと、形の違いを両方向で断ること、順の違いを断ること、`guard` で形を照らすこと、JSON の照らし、同じ承認を 2 回消費できないこと
- lock の確かめ: 親を KILL した後に次の実行が lock を取れること、グループに TERM や HUP を送っても後片付けが終わるまで lock が離れないこと、lock を取れずに止まる実行では後片付けも戻しも走らないこと
- 承認の同時消費は、承認の置き場所を一時フォルダーに差し替えて `use-approval` を 2 つ同時に流し、成功が 1 件だけになることを照らす（本物の `~/Library/...` には書かない）
- シェルの部分は、端末の操作をまねる関数に差し替えて、**`test_ios_ui.sh` と `verify_unity_ios.sh` の両方で**流す（シミュレーターの回とは別）。実機の形で、待ちの間に TERM を受けた後に 3 つのアプリの uninstall が呼ばれることも照らす: 偽の印・別の実行の印・場所の印を認めないこと、待つ間に HEAD が動いたら始めないこと、待ちの時間切れ、TERM で止めたときに後片付けが最後まで走ること、消している途中で TERM を受けても残りを消すこと、走っている間に編集した `ProjectSettings` が終わりに戻されないこと
- シミュレーターで `--keep-installed` を流す（印のファイルを agent が作る）。シミュレーターでは集中モードは関係ないが、入れ直さずに 5 件が順に通ることと、後片付けを確かめる
- 実機は、利用者の準備（集中モード）と許可を得てから流す

## 4. 今のランナーにもある穴（この設計を待たずに直す）

**`test_ios_ui.sh` と `verify_unity_ios.sh` の両方**にある（レビュー v2 の R-1）。

- 終わりの `restore_side_effects` は、Unity の段の直後に戻した後も実行の終わりにもう一度走り、走っている間に人が編集した `ProjectSettings` などまで戻す（Codex の KI-01）。Unity の段ごとに「始める前に印を立て、戻し終えたら下ろす」形にし、終わりの一括の戻しは印が立っているとき（Unity の段の途中で止まったとき）だけにする。`verify_unity_ios.sh` には Unity の段が 3 つある。Editor の 2 段（EditMode と Editor の PlayMode）は間に戻しが無いので、1 つの段として扱い、前に印を立て、2 段の後の戻しが済んだら下ろす
- `clean_up_apps`（`test_ios_ui.sh`）と `clean_up_player`（`verify_unity_ios.sh`）は消す前に「済んだ」の印を立てるので、消している途中で止められると trap が残りを消さない（Codex の KI-02）。消し終えて確かめてから印を立てる

## 5. 決めていないこと

- 印のファイルの代わりに、端末の上でハーネスが「許可するアプリに入っている」ことを確かめる方法は無い（集中モードの設定はアプリから読めない）。足し忘れは、NU-4 のバナーが出ないことで分かる（落ちて後片付けに進む）
